# 작업 규칙

## 작업 범위

- 과제와 관련된 파일은 `spring-fw-juwonlee/` 안에서만 읽고 수정한다. 다른 학생의 디렉토리나 저장소 루트 파일은 수정하지 않는다.
- Git 상태와 브랜치를 확인하는 명령은 저장소 루트에서 실행할 수 있지만, 파일 변경은 이 디렉토리 안에서만 한다.
- 사용자가 명시적으로 요청하지 않는 한 commit, push, merge, rebase 등 저장소 이력을 바꾸는 작업은 수행하지 않는다.
- 과제와 무관한 기존 변경사항을 덮어쓰거나 정리하지 않는다.
- 사용자가 직접 처리한다고 한 과제 결과 이미지의 캡처 및 Issue/PR 첨부는 수행하지 않는다.

## 매주 과제 시작 절차

1. `gh` CLI로 해당 주차의 GitHub Issue를 확인한다. 과제 설명 외에 일정, 공지, 운영 안내가 섞여 있을 수 있으므로 전체 내용을 검토한다.
2. 구현에 필요한 목표, 필수 요구사항, 제출물, 제약 및 완료 조건을 운영 안내와 구분한다. 불명확하거나 서로 모순되는 과제 조건은 임의로 확정하지 말고 사용자에게 알린다.
3. Issue 내용을 기준으로 저장소의 현재 파일 구조와 기존 주차 구현을 살펴본다. 기존 패턴과 충돌하거나 과제 범위를 넓히는 변경은 피한다.
4. 과제 조건을 작업 중 계속 참조할 필요가 있으면 해당 주차 폴더에 `ASSIGNMENT.md`를 만들고 과제 수행에 필요한 내용만 요약한다. 주차별 목표와 제출물은 이 파일에만 기록하고 이 공통 규칙 파일에는 넣지 않는다.
5. 작업 전 Git 상태, 현재 브랜치, worktree 목록을 확인한다. 주차 작업 브랜치 이름은 `weekN/juwonlee` 형식을 사용한다(예: `week10/juwonlee`). 대상 브랜치가 이미 존재하거나 다른 worktree에서 사용 중이면 중복 생성이나 강제 체크아웃을 하지 말고 사용자에게 현재 상태와 충돌을 알린다. 기존 변경사항을 보존하며, 브랜치 전환이나 생성은 과제 시작에 필요한 범위에서만 수행한다.
6. Issue에 필요한 구현 위치만 추가하거나 수정한다. 매주 XML 리소스나 `weekN` 하위 패키지/Java 파일을 새로 만들 필요는 없다. 해당 주차 과제에 필요하지 않다면 기존 XML을 그대로 사용하고, 불필요한 주차 폴더나 파일을 만들지 않는다.
7. 과제 실행 진입점인 `src/main/java/com/fw/Main.java`를 해당 주차 과제가 정상적으로 실행되도록 필요한 범위에서 조정한다.
8. 새 주차 과제의 구현은 해당 주차에 새 파일을 만들어 진행한다. 이전 주차 디렉토리의 파일은 GitHub Issue에 그 파일의 수정을 명확히 요구한 경우에만 수정한다. Issue에 명시되지 않았다면 어떤 경우에도 이전 주차 디렉토리 파일을 다른 주차 과제를 위해 변경하지 않는다.
9. `Main.java`와 `src/main/resources/*.properties`처럼 공통 실행 설정에 해당하는 파일은 여러 주차에서 수정이 필요할 수 있다. 그 외 파일은 위의 이전 주차 파일 보호 규칙을 따른다.
10. Issue의 요구사항을 충족하도록 구현하고, 관련 코드와 설정은 저장소의 기존 주차별 명명 및 디렉토리 패턴을 따른다. 검증은 과제 조건과 사용자의 요청에 맞춰 수행한다.
11. 완료 시 변경 파일과 요구사항 충족 여부, 수행한 검증 및 남은 사항을 간단히 보고한다. commit이나 push는 별도 요청이 있을 때만 한다.
12. 커밋을 사용자가 명시적으로 요청한 경우에만 수행하고, 커밋 메시지는 Conventional Commits의 유형 접두사(`feat`, `fix`, `refactor`, `docs`, `test`, `chore` 등) 뒤에 한국어로 요약한다. 예: `feat: 리소스 조회 기능 구현`.

## 기존 프로젝트 패턴

- 프로젝트는 Gradle Java 프로젝트다. 주차별 Java 코드는 `src/main/java/com/fw/weekN/`, 주차별 XML 설정은 필요에 따라 `src/main/resources/weekN.xml`에 둔다.
- 위 경로는 필요에 따라 사용하는 관례이지 매주 파일을 만들어야 한다는 뜻이 아니다. Issue에서 다루지 않는 XML은 이전 것을 유지하고, 과제에 해당하지 않는 주차별 Java 파일이나 패키지는 추가하지 않는다.
- `src/main/java/com/fw/Main.java`는 현재 수행할 주차 과제를 실행하도록 연결한다. 공통 실행 진입점 및 `src/main/resources/*.properties`를 제외한 이전 주차 파일은 Issue가 수정을 명확히 요구하지 않는 한 보존한다.
- 기존 파일의 이름과 패키지 구조를 먼저 확인하고, 새 파일도 해당 주차의 패턴에 맞춘다. 모든 주차에 동일한 파일 구성이 있다고 가정하지 않는다.
- Spring Boot의 표준과 관례를 적용 가능한 범위에서 따른다. 현재 프로젝트 구성이 Spring Framework 기반이면 Issue가 요구하지 않는 한 Spring Boot 의존성 추가나 프로젝트 전환은 하지 않고 기존 구성에 맞춰 적용한다.
- Lombok 및 Spring이 제공하는 어노테이션(예: `@Slf4j`, `@Service`, `@Configuration`, `@Bean`)을 적절히 활용해 반복 코드를 줄이고 역할을 명확히 한다. 의미 없이 어노테이션을 추가하지 않는다.
